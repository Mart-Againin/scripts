# TG Analytics

Скрипт для автоматического сбора статистики Telegram-каналов, построения Excel-отчётов и управленческих PowerPoint-дашбордов, с выгрузкой в Google Таблицы. Работает как постоянно запущенный процесс, управляется командами в Telegram.

## Возможности

- Ежечасный сбор статистики постов и сторис по списку каналов
- Точная фиксация показателей через 24 часа после публикации («замороженные» цифры вместо промежуточных)
- Суточные / недельные / месячные Excel-отчёты с разбивкой по постам, дням, неделям
- Управленческий PowerPoint-дашборд: динамика за 6 месяцев, сравнение со средним за 5 месяцев, лучшие и худшие посты, платные размещения
- Учёт платных размещений (посевов): из Google Таблицы, при её отсутствии — из локального файла
- Выгрузка месячного отчёта в Google Таблицу
- Управление командами в Telegram, перезапуск с подтверждением — без доступа к консоли сервера

## Требования

- Python 3.11+
- Node.js и npm-пакет [pptxgenjs](https://www.npmjs.com/package/pptxgenjs) — для сборки PPTX-дашборда (без него остальное работает, дашборд — нет)
- Telegram-аккаунт (юзербот через [Telethon](https://docs.telethon.dev/), не Bot API) и `api_id` / `api_hash` с [my.telegram.org](https://my.telegram.org)
- *(необязательно)* сервисный аккаунт Google — для выгрузки отчётов и чтения таблицы посевов

## Установка

```bash
pip install -r requirements.txt
npm install -g pptxgenjs
```

Скопируйте `.env.example` в `.env` и заполните значения (см. ниже).
Если `pptxgenjs` установлен не в стандартное место, укажите путь в `.env`: `NODE_MODULES_PATH` (результат команды `npm root -g`).

При первом запуске `python main.py` потребуется интерактивный вход в Telegram (QR-код или код из приложения). Сессия сохраняется в файл `<SESSION_NAME>.session` — дальше вход не нужен.

## Настройка (.env)

Полный список с комментариями — в `.env.example`. Основное:

| Переменная | Назначение |
|---|---|
| `API_ID`, `API_HASH` | Ключи доступа к Telegram |
| `SESSION_NAME` | Имя файла сессии |
| `CHANNELS` | Отслеживаемые каналы через запятую: `@channel_one,@channel_two` |
| `REPORT_RECIPIENT_ID` | Кому слать отчёты (числовые user id через запятую) |
| `DEBUG`, `DEBUG_RECIPIENT_ID` | Тестовый режим: при `DEBUG=true` отчёты уходят только на `DEBUG_RECIPIENT_ID` |
| `MODERATOR_IDS` | Кто ещё может слать команды боту |
| `DAILY_REPORT_TIME`, `TIMEZONE` | Время суточного отчёта и часовой пояс |
| `GOOGLE_SHEETS_CREDENTIALS` | Путь к JSON-ключу сервисного аккаунта |
| `GOOGLE_SHEETS_ID` | ID таблицы для выгрузки месячных отчётов |
| `GOOGLE_PAID_SHEET_URL` | Ссылка на таблицу платных размещений |

Обе Google-таблицы должны быть расшарены (Editor) на `client_email` из JSON-ключа. Проверить подключение: `python check_google_sheets.py`.

## Запуск и остановка

```bash
python main.py
```

Остановка — `Ctrl+C` в окне процесса. Процесс должен работать непрерывно; расписание проверяется изнутри скрипта раз в минуту, отдельный планировщик (cron / Планировщик заданий) не нужен.

## Команды в Telegram

Команды принимаются только от пользователей из `REPORT_RECIPIENT_ID`, `DEBUG_RECIPIENT_ID`, `MODERATOR_IDS`.

| Команда | Действие |
|---|---|
| `/report daily \| weekly \| monthly \| dashboard` | Сформировать отчёт или дашборд |
| `/upload monthly [YYYY-MM]` | Выгрузить месяц в Google Таблицу (по умолчанию — прошлый месяц). Лист месяца **перезаписывается целиком** |
| `/backfill` | Ретро-сбор исторических данных |
| `/import_paid` | Загрузить платные размещения из файла (xlsx/csv) прямо в чате |
| `/inspect @channel msg_id` | Сырая диагностика одного поста |
| `/restart` | Перезапустить бота (подхватить изменения в коде) |
| `/help` | Список команд |

## Перезапуск (`/restart`)

`/restart` запускает **новый** процесс, после чего старый корректно завершается. Подтверждение приходит отдельным сообщением от нового процесса:

- `✅ Перезапуск выполнен успешно` — с PID обоих процессов и датой изменения ключевых файлов (видно, какая версия кода загружена);
- `❌ Перезапуск НЕ выполнен: …` — новый процесс упал сразу после старта (например, ошибка в коде); старый продолжает работать;
- `⚠️ … старый процесс не завершился` — с командой для ручного завершения.

Если «✅» не пришло в течение минуты — смотрите окно нового процесса и строки `[RESTART]` в `logs/main.log`. На Windows новый процесс открывается в новом окне консоли (отключается `RESTART_NEW_CONSOLE=0`).

## Архитектура данных

Два источника постов объединяются перед построением любого отчёта:

- **`historical.py`** — полный список постов за период напрямую из Telegram (с локальным кэшем по месяцам). Текущий, ещё идущий месяц **никогда не берётся из кэша**.
- **`registry.json`** (собирает `snapshot.py` раз в час) — точные 24-часовые срезы: когда посту исполняется 24 часа, его статистика фиксируется и больше не меняется.

Где есть зафиксированный срез — используется он, для остальных постов — актуальные данные из полного списка.

История показателей по месяцам (`registry/history_db.json`, питает графики динамики) пишется только при генерации месячного Excel-отчёта. Число подписчиков фиксируется один раз и не переписывается; охват, ERR и VRpost обновляются при каждой пересборке.

Платные размещения: если в Google Таблице есть лист нужного месяца («Сентябрь 2026») — используется только он; локальный файл `registry/paid_placements.json` — запасной вариант, когда листа нет.

## Хранилище

Все данные — JSON-файлы на диске, отдельной СУБД нет:

```
registry/<канал>/registry.json              — посты с 24ч-срезами
registry/<канал>/historical/YYYY-MM.json    — кэш полных выгрузок по месяцам
registry/<канал>/subscribers_history.json   — ежедневные снимки подписчиков
registry/history_db.json                    — история показателей по месяцам
registry/paid_placements.json               — платные размещения (локальный источник)
archive/                                    — посты старше определённого срока
output/                                     — Excel-отчёты и PPTX-дашборды
logs/main.log                               — лог процесса
```

Эти папки в репозиторий не попадают (`.gitignore`), но их нужно копировать при переносе на другой сервер вместе с `.env` и файлом сессии.

## Вспомогательные инструменты

Запускаются вручную из папки проекта. Те, что подключаются к Telegram, используют тот же файл сессии, что и бот, — **запускайте их только при остановленном боте** (два процесса на одной сессии дают обрывы соединения).

| Скрипт | Telegram | Назначение |
|---|---|---|
| `check_google_sheets.py` | нет | Проверка ключа и доступа к обеим Google Таблицам |
| `check_history_db.py` | нет | Просмотр `history_db.json` без изменений |
| `import_manual_stats.py` | нет | Ручная загрузка охвата/ERR/VRpost за прошлые периоды (образец: `manual_stats.example.csv`) |
| `import_subscribers.py` | нет | Ручная запись числа подписчиков (образец: `subscribers.example.csv`) |
| `import_paid_placements.py` | нет | Загрузка платных размещений из xlsx/csv (то же делает `/import_paid`) |
| `import_from_existing_reports.py` | нет | Загрузка показателей из уже готовых месячных Excel-отчётов |
| `audit_snapshot_coverage.py` | да | Какие посты есть в Telegram, но не попали в `registry.json` |
| `audit_poll_votes.py` | да | Голоса по всем опросам месяца |
| `check_post.py`, `inspect_raw_post.py` | да | Диагностика одного поста (то же делает `/inspect` без остановки бота) |
| `refetch_texts.py` | да | Пересборка кэша `historical/` по месяцам |
| `fix_history_month.py`, `force_recompute_month.py` | да | Принудительный пересчёт записи месяца в `history_db.json` |
| `backfill_vrpost.py` | да | Одноразовый расчёт VRpost по кэшу за прошлые месяцы |

## Известные особенности

- Файл сессии Telegram нельзя использовать из двух процессов одновременно.
- На сервере должна работать синхронизация времени (в Windows — служба `w32time`): рассинхронизация часов вызывает серии ошибок соединения с Telegram.
- Нужен `telethon>=1.45`: более старые версии не распознают часть типов медиа (например, опросы с картинкой).
- `/upload monthly` берёт посты только из `registry.json` (без наложения на полный список, как это делают Excel-отчёт и дашборд), поэтому при пропусках почасового сборщика в Google Таблице может оказаться меньше постов, чем в Excel.
- Поля «Переход», «Достижение цели», «Коммент» в Google Таблице заполняются вручную и **стираются** при повторной выгрузке того же месяца.
